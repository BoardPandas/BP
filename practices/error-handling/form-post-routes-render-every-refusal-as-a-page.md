# A route reached by a native form post renders every refusal as a page

## PATTERN
A route that a browser reaches by submitting an HTML form (not by `fetch`) answers every refusal with an **HTML page**, never raw JSON. "Every" includes the refusals the handler never sees:

1. The handler's own validation and authorization errors.
2. The **router's** responses for that path: `405 Method Not Allowed` when the path is opened with the wrong method (for example someone reloads or pastes the URL and the browser sends a GET), and `404`.
3. **Layer-level** errors raised before the handler runs: body-size limit, rate limit, timeout, origin or CSRF refusal, malformed body.

Decide by route, not by error type: the set of form-post routes is known, and for those routes the error renderer produces a page with a way back.

## WHY
With `fetch`, the page's own code receives the error and shows something sensible. With a native form post, the response **replaces the page**. A JSON error body is then what the person sees: a line of raw JSON in an otherwise blank tab, with no navigation and no explanation. Handlers are usually written to return pages, but the router's 405 and the outer layers' errors are generated elsewhere, in the API's default format, and they are the ones that get missed.

## EXAMPLE
Generic sketch:

```text
FORM_POST_ROUTES = ["/account/devices/profile", "/oauth/decision", ...]

error_response(request, status, kind):
    if request.path in FORM_POST_ROUTES:
        return html_page(status, message_for(kind), link_back_for(request.path))
    return json_error(status, kind)

router:
    for each path in FORM_POST_ROUTES:
        POST  -> handler
        other methods -> error_response(request, 405, "method_not_allowed")   # not the router default

outermost layer:
    converts every error raised by inner layers (413, 429, 408/504, 403 origin/CSRF)
    through error_response, so the same route decision applies
```

## CHECK
- [ ] There is an explicit list (or marker) of routes reached by native form posts.
- [ ] A GET to each of those routes returns an HTML page with status 405, not the router's default body.
- [ ] An oversized body, a rate-limited request and a failed origin or CSRF check on each route return HTML pages.
- [ ] A test asserts `Content-Type: text/html` for each refusal on each form-post route.

## IMPLEMENT
1. List the form-post routes.
2. Route all error rendering through one function that chooses page or JSON by route.
3. Register explicit method fallbacks for those paths so the 405 goes through it.
4. Make the outermost layer convert inner-layer errors through the same function.
5. Add the per-route refusal tests.

## NOTES

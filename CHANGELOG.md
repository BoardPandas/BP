# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Fixed
- **A 13 KB runbook was unreachable.** `practices/claude-config/claude-wiring-audit.md` -- the portable two-phase checklist for auditing another repo's `.claude/` wiring, including the Phase 2 checks a script cannot make (has any hook ever actually fired, silenced hooks, blocking hooks that never reach stderr) -- was linked from no `llms.txt` and referenced by no entry, so the only way to find it was to already know its path. It is now referenced from `verify-claude-wiring-in-ci.md` (its automated counterpart) and listed under a new **Companion files** section on the `claude-config` shelf, alongside `check-claude-wiring.mjs`. Companion files sit outside `## Entries`, so they are reachable without inflating the shelf's count.
- **Three entries could not be applied mechanically.** `database/drizzle-custom-backfill-flow.md`, `deployment/host-mode-rollout.md` and `notifications/multi-channel-dispatcher.md` had no `## CHECK` or `## IMPLEMENT` -- the two sections `/apply-practice` reads -- so the skill had nothing to act on rather than failing loudly. All three now carry both, written from each entry's own PATTERN. The first two also gained the `tech:` key they were missing, and all three gained `applies-to:`.
- Line endings are pinned by `.gitattributes` (`* text=auto eol=lf`) before BP could repeat LL-G's failure, where CRs accumulated and a later LF-only rewrite turned each one into a real blank line -- quadrupling the master index while its content stayed flat. 154 files normalized to LF.

### Changed
- **The master index is a router, not a summary.** Two concern descriptions had grown into run-on sentences that enumerated the practices instead of pointing at them -- `resource-lifecycle` at 725 bytes and `llm-resilience` at 201 -- which is the same drift that took LL-G's index to 51 KB of always-on context. Both are now one clause naming the concern and its scope, and the file carries a note stating the ceiling for whoever writes the next line.
- **Northflank dropped in favour of two infrastructure profiles.** `practices/deployment/doppler-secrets.md` now syncs production secrets to Cloudflare and **Railway** instead of Northflank, and names the mechanism for each: `wrangler secret bulk` on Cloudflare, Doppler's native Railway integration (continuous sync, no code) on Railway. The deployment index blurb, the master `llms.txt` index line, and the README tree were updated to match. Three Northflank mentions were deliberately kept: the LL-G cross-reference in `dual-read-key-rotation.md` (the linked lesson is named for it), the quoted plan excerpt in `phase-split-remediation-plans.md` (a real historical example), and the MCP column in `repo-inventory.md` (a factual record of what a repo actually runs).
- **Synced `.claude/skills/plan-repo` and `.claude/skills/init-repo` to the `claude-code-bootstrap` template.** Hosting is no longer a single locked stack: server-side work now targets one of two profiles picked whole -- Cloudflare (Workers, D1 or Hyperdrive-fronted Postgres, KV/Durable Objects, Queues, Cron Triggers, native CDN) or Railway (container services, Postgres, Redis, cron, volumes, Cloudflare proxy in front) -- chosen by a research subagent rather than assumed. plan-repo also gains a desktop track (delivery-target question routing to framework, UI/local-data, and packaging/signing/update research) and runs its research in three waves, since the platform pick constrains the language, framework, and ORM prompts downstream. `.claude/references/infrastructure.md` is added alongside, which the skill has always referenced but this repo never carried.
- **feedback-widget template: multiple screenshots by default.** The tier-2 flow now accepts up to `FEEDBACK_SCREENSHOT_MAX_COUNT` (4) screenshots per submission (multi-file picker + multi-image paste, thumbnail grid, per-item remove). `buildFeedbackGithubIssue` renders them all in one `### Screenshots` section, `buildFeedbackSlackMessage` adds a links row, the submission schema takes `screenshotKeys[]` (deprecating `screenshotKey`), and the presign rate limit is sized to the attachment cap so a full set plus a retry fits one window. Backported from the SupportForge deployment; SPEC.md and HANDOFF.md document the two multi-screenshot traps (parallel-upload rate limiting, per-attachment unique repo paths).
- **Synced `.claude/references/hooks-and-settings.md` to Claude Code 2.1.201** from the `claude-code-bootstrap` template: hook structured output (`updatedToolOutput`, `additionalContext`, `reloadSkills`/`sessionTitle`), `Tool(param:value)` parameter matching, HTTP hook custom headers with env-var interpolation, the `PermissionRequest` auto-approval pattern, new settings (`defaultMode` rename, `fallbackModel`, `enforceAvailableModels`, `disableBundledSkills`, `requiresMinimumVersion`), the full six-tier settings precedence chain, and the `ENABLE_PROMPT_CACHING_1H` cache lever.

### Added
- **A guard script and CI, neither of which BP had** (`scripts/check-practices.mjs`, `.github/workflows/ci.yml`, `package.json`). Every `(N entries)` count in the master index was maintained by hand, in a second place, and verified by nobody; a file nothing linked was indistinguishable from a file that did not exist. `npm run check` now asserts counts against each shelf, that every file on disk is linked from its shelf index, that `concern:`/`tech:`/`priority:` hold and the concern matches its folder, and that every entry has `PATTERN` plus a rationale section plus the `CHECK`/`IMPLEMENT` that `/apply-practice` depends on. Negative-tested in the blocking direction: count drift, an unreachable file, and a missing `## CHECK` each exit 1. `source-repo:`/`applies-to:` are reported as warnings rather than failures, because three entries predate the convention and their source repo is not recorded anywhere -- see the note below.
- **New `user-feedback` concern** with the entry *Portable In-App Feedback Widget (Button to GitHub Issue)*, plus the full code template at `templates/feedback-widget/` (17 generalized source files + HANDOFF.md install sheet), extracted from the Vigilis dashboard.
- **Added this CHANGELOG**, mirroring the LL-G knowledge-base repo so config changes are tracked here too.
